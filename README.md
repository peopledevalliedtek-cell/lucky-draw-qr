# ระบบจับฉลากของรางวัลด้วย QR Code

**แนวคิด**: ป้ายชื่อเป็นป้ายเปล่า พนักงานไปหยิบเองตอนเข้างาน (เขียนชื่อตัวเองด้วยมือ) — QR
บนป้ายแต่ละใบถูกผูกกับ **ของรางวัลชิ้นหนึ่งไว้ล่วงหน้าแบบสุ่มและสับไพ่แล้ว** ดังนั้นการที่พนักงานหยิบป้ายไหนก็คือการจับฉลากไปในตัว ("ดวงใครดวงมัน")
ตอนเย็นแอดมิน "เปิดระบบ" แล้วพนักงานค่อยสแกน QR ที่ป้าย → กรอกรหัสพนักงาน → ระบบเด้งชื่อ-แผนกมาให้ตรวจสอบ พร้อมของรางวัลที่ได้ → กด "ยืนยัน" เพื่อล็อกสิทธิ์

ข้อมูลที่ใช้สร้างระบบนี้:
- พนักงาน 197 คน (ATE 138 / ATT 59) จากไฟล์ ATT-ATE EmpData
- ของรางวัล 26 รายการ รวม 205 ชิ้น จากไฟล์ Plan_Budget_HNY_2026 ชีท "ของรางวัล" → สร้างเป็นป้าย (badge) 205 ใบ ใบละ 1 ของรางวัล สับลำดับแบบสุ่มแล้ว

## ขั้นตอนใช้งานจริงในวันงาน

1. **ก่อนงาน**: สร้าง QR + พิมพ์ป้ายชื่อเปล่า (ดูหัวข้อ "วิธีสร้าง QR" ด้านล่าง) เอาไปวางกองรวมกันที่โต๊ะลงทะเบียน
2. **ตอนเข้างาน**: พนักงานมาหยิบป้ายเอง 1 ใบ เขียนชื่อตัวเองติดตัว (ยังไม่สแกน)
3. **ตอนเย็น**: แอดมินกดสวิตช์ "เปิดระบบ" ที่หน้า `/admin`
4. พนักงานสแกน QR ที่ป้ายตัวเอง → กรอกรหัสพนักงาน → ระบบเด้งชื่อ-แผนก+ของรางวัลให้ตรวจสอบ → กด "ยืนยันรับรางวัล"
5. แอดมินดูผลสรุปและสต็อกคงเหลือแบบเรียลไทม์ที่หน้า `/admin`, กด export CSV ได้

**กันเหตุการณ์ซ้ำซ้อน**: ถ้ากรอกรหัสพนักงานที่เคยยืนยันรับรางวัลไปจากป้ายอื่นแล้ว ระบบจะบล็อกทันทีและแจ้งว่าได้รับไปแล้ว (เผื่อพนักงานหยิบป้ายไปหลายใบ) / ถ้าป้ายใบนั้นมีคนอื่นสแกนยืนยันไปแล้ว ระบบจะแจ้งว่าป้ายถูกใช้แล้ว

## ฐานข้อมูล: ใช้ Supabase (ไม่ใช่ไฟล์ในเครื่องแล้ว)

เวอร์ชันนี้เก็บข้อมูลบน **Supabase** (Postgres บนคลาวด์ ฟรีสำหรับงานขนาดนี้) แทนไฟล์ SQLite ในเครื่อง
ข้อดี: ไม่มีขั้นตอนคอมไพล์โค้ด native ตอน `npm install` อีกเลย (ปัญหา Node version ที่เคยเจอหมดไป) และข้อมูลไม่หายแม้เครื่องรันเซิร์ฟเวอร์ดับ

**ขั้นตอนตั้งค่า Supabase (ทำครั้งเดียว):**

1. สมัคร/ล็อกอิน [supabase.com](https://supabase.com) แล้วกด "New project" (เลือกแผนฟรีได้)
2. รอโปรเจกต์สร้างเสร็จ (1-2 นาที) แล้วไปที่เมนู **SQL Editor** → New query
3. เปิดไฟล์ `scripts/schema.sql` ในโฟลเดอร์นี้ คัดลอกทั้งหมดไปวาง แล้วกด **Run** (สร้างตาราง + ฟังก์ชันที่จำเป็นทั้งหมดให้อัตโนมัติ)
4. ไปที่ **Project Settings → API** คัดลอก 2 ค่านี้เก็บไว้:
   - **Project URL** (หน้าตาแบบ `https://xxxxxxxxxxxx.supabase.co`)
   - **service_role key** (อยู่ใต้หัวข้อ "Project API keys" — ใช้ตัวที่เขียนว่า `service_role` **ไม่ใช่** `anon` **public**)

## วิธีติดตั้ง (รันบนเครื่อง/เซิร์ฟเวอร์ของบริษัท)

ต้องมี Node.js (เวอร์ชัน 18 ขึ้นไป) ติดตั้งไว้ก่อน — เวอร์ชันนี้ไม่มี native dependency แล้ว ใช้ Node เวอร์ชันไหนก็ได้ที่เป็น 18+

```bash
cd luckydraw
cp .env.example .env       # แล้วเปิดไฟล์ .env ด้วย Notepad ใส่ค่า SUPABASE_URL กับ SUPABASE_SERVICE_ROLE_KEY ที่คัดลอกมาจากขั้นตอนก่อนหน้า
npm install
npm run seed                # โหลดรายชื่อพนักงาน+ของรางวัลขึ้น Supabase + สุ่ม/สับป้าย 205 ใบ
npm start                   # เริ่มเซิร์ฟเวอร์ (ค่าเริ่มต้นที่ http://localhost:3000)
```

`npm run seed` รันครั้งแรกเท่านั้นที่จะสุ่ม/สับป้ายใหม่ — รันซ้ำอีกจะไม่แตะป้ายที่สร้างไปแล้ว (กันไม่ให้ QR ที่พิมพ์ไปแล้วเปลี่ยนความหมาย)

เปลี่ยนรหัสผ่านแอดมินก่อนใช้งานจริง — แก้ในไฟล์ `.env` ที่ `ADMIN_USER` / `ADMIN_PASS` (ดูหัวข้อ "ความปลอดภัย" ด้านล่าง)

## วิธีสร้าง QR Code ติดป้ายชื่อ

**สำคัญ**: ต้องรู้ก่อนว่าจะ deploy เซิร์ฟเวอร์ไว้ที่ domain/URL อะไรที่มือถือพนักงานเข้าถึงได้
(เช่น URL ของเซิร์ฟเวอร์บริษัท หรือ URL จากบริการ hosting ที่เลือกใช้ — ดูหัวข้อถัดไป) และต้องรัน `npm run seed` ไปแล้วอย่างน้อย 1 ครั้ง

```bash
BASE_URL=https://ลิงก์เซิร์ฟเวอร์ของคุณ npm run badges
```

จะได้ไฟล์:
- `output/badges.html` — ชีทป้ายชื่อเปล่าพร้อมพิมพ์ (3 คอลัมน์ต่อหน้า) มีช่องเขียนชื่อด้วยมือ + QR เท่านั้น **ไม่มีการเปิดเผยของรางวัลบนป้าย** เปิดด้วยเบราว์เซอร์แล้วกด Print หรือ Print to PDF ได้เลย
- `output/admin_manifest.csv` — ไฟล์ลับ (badge token ↔ ของรางวัล) สำหรับทีมงานเก็บไว้ตรวจสอบเองเท่านั้น **ห้ามแชร์หรือพิมพ์ให้พนักงานเห็นเด็ดขาด**

## หน้าแอดมิน (เปิด/ปิดระบบ, ดูผล, สต็อกคงเหลือ, export)

เข้า `https://ลิงก์เซิร์ฟเวอร์ของคุณ/admin` (ต้อง login ด้วย Basic Auth)
- user: ตาม `ADMIN_USER` (ค่าเริ่มต้น `admin`)
- password: ตาม `ADMIN_PASS`

หน้านี้มี:
- สวิตช์เปิด/ปิดระบบ (ก่อนกดเปิด พนักงานสแกนแล้วจะเห็นแค่ "ยังไม่เปิดให้จับฉลาก")
- จำนวนคนที่จับฉลากแล้ว / ป้ายที่ถูกใช้แล้ว
- สต็อกคงเหลือแต่ละของรางวัลแบบเรียลไทม์ — ตัวเลขขึ้นทันทีที่มีคนยืนยันรับรางวัล ไม่ต้องรีเฟรชหน้าเอง (จุดเขียว "● เรียลไทม์" บนหัวข้อแปลว่าเชื่อมต่อสำเร็จ)
- ปุ่มดาวน์โหลดผลทั้งหมดเป็น CSV
- ปุ่ม "📺 เปิดจอ Live Wall" — เปิดแท็บ/หน้าต่างใหม่สำหรับโปรเจคเตอร์หรือจอทีวีหน้างาน (ดูหัวข้อถัดไป)

## จอ Live Wall (โชว์ผู้โชคดีสดๆ หน้างาน)

เข้า `https://ลิงก์เซิร์ฟเวอร์ของคุณ/live` (หน้านี้ไม่ต้อง login — เปิดฉายขึ้นจอใหญ่ได้เลย เพราะข้อมูลที่โชว์คือสิ่งที่พิธีกรประกาศอยู่แล้วหน้างาน)

พอมีใครกด "ยืนยันรับรางวัล" ที่มือถือ ชื่อ+ของรางวัลจะเด้งขึ้นจอใหญ่ทันทีพร้อมเอฟเฟกต์ confetti โดยไม่ต้องรีเฟรชหน้า (ใช้เทคโนโลยี Server-Sent Events ส่งสัญญาณแบบเรียลไทม์จากเซิร์ฟเวอร์)

## จะเอาไปรันที่ไหน (ตัวเลือก deploy)

ระบบนี้เป็น Node.js app ธรรมดา รันได้บน:
- เซิร์ฟเวอร์/โน้ตบุ๊กของบริษัทเอง ในวง LAN เดียวกับงานเลี้ยง (ใช้ IP เครื่อง เช่น `http://192.168.1.50:3000`) — เหมาะที่สุดถ้าจัดงานในสถานที่ที่ไม่มีเน็ตสาธารณะ
- บริการ hosting ฟรี/ราคาถูกที่รองรับ Node.js เช่น Render, Railway, Fly.io (รันคำสั่ง `npm install && npm run seed && npm start`)

### Deploy บน Render.com (จากโค้ดใน repo นี้โดยตรง)

repo นี้มีไฟล์ `render.yaml` (Render Blueprint) อยู่แล้ว ทำให้ตั้งค่าได้ไวขึ้นมาก:

1. สมัคร/ล็อกอิน [render.com](https://render.com) ด้วยบัญชี GitHub (ให้สิทธิ์เข้าถึง repo `peopledevalliedtek-cell/lucky-draw-qr`)
2. หน้า Dashboard → **New** → **Blueprint** → เลือก repo นี้ → Render จะอ่าน `render.yaml` แล้วสร้าง Web Service ให้อัตโนมัติ
3. ตอนตั้งค่า จะมีช่องให้กรอก environment variables 4 ตัว (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_USER`, `ADMIN_PASS`) — กรอกค่าตามที่ได้จากขั้นตอน Supabase ด้านบน
4. กด **Apply** / **Create Web Service** — รอ build เสร็จ (ไม่กี่นาที) จะได้ลิงก์ติดตั้งแบบ `https://lucky-draw-qr-xxxx.onrender.com`
5. เข้า Render Dashboard → service นี้ → **Shell** tab → รันคำสั่ง `npm run seed` ครั้งเดียว (สร้างฐานข้อมูล + สุ่ม/สับป้าย)
6. ทดสอบเข้า `https://ลิงก์ที่ได้/admin` เพื่อเปิดระบบและลองสแกน QR ก่อนใช้งานจริง

**หมายเหตุ**: แผน Free ของ Render จะ "sleep" เซิร์ฟเวอร์เมื่อไม่มีคนเข้าใช้นานเกิน ~15 นาที แล้วปลุกตัวเองใหม่ตอนมีคนเข้า (ใช้เวลาประมาณ 30-60 วินาทีครั้งแรก) ถ้ากังวลเรื่องนี้ตอนงานจริง แนะนำให้อัปเกรดเป็นแผนเสียเงินราคาถูก (Starter ~$7/เดือน) เพื่อให้เซิร์ฟเวอร์พร้อมใช้ตลอดเวลาช่วงงานเลี้ยง

ไม่ว่าจะเลือกวิธีไหน ให้สร้าง QR code **หลังจาก** รู้ URL จริงแล้วเท่านั้น (ใช้ `BASE_URL=... npm run badges`)
มิเช่นนั้น QR จะชี้ไปที่ `localhost` ซึ่งมือถือพนักงานเข้าไม่ได้

เนื่องจากข้อมูลอยู่บน Supabase แล้ว **ไม่ว่าจะรันเซิร์ฟเวอร์ที่เครื่องไหน ข้อมูลเชื่อมกันหมด** — จะสลับรันจากโน้ตบุ๊กเครื่องอื่น หรือ deploy ขึ้น Render ภายหลัง ก็ไม่ต้องย้ายไฟล์ฐานข้อมูลเอง เพียงตั้งค่า `.env` ให้ชี้ไปที่ Supabase โปรเจกต์เดียวกัน (แต่ **ต้องมีอินเทอร์เน็ต** ตลอดเวลาที่เซิร์ฟเวอร์รันอยู่ ทั้งฝั่งเครื่องรันเซิร์ฟเวอร์และฝั่งมือถือพนักงานที่สแกน)

## ความปลอดภัย

1. เปลี่ยนรหัสผ่านแอดมิน ก่อนใช้งานจริงเสมอ แก้ค่า `ADMIN_USER` / `ADMIN_PASS` ในไฟล์ `.env`
2. **ไฟล์ `.env` ห้ามแชร์หรือ commit ขึ้น git เด็ดขาด** เพราะมี `SUPABASE_SERVICE_ROLE_KEY` ซึ่งเป็นกุญแจที่เข้าถึง/แก้ไขข้อมูลทุกตารางได้แบบไม่จำกัด (ใช้ได้เฉพาะฝั่งเซิร์ฟเวอร์เท่านั้น ไม่เคยส่งไปที่หน้าเว็บฝั่งพนักงาน)
3. Token ของแต่ละป้ายถูกสุ่มแบบคาดเดายาก ฝังอยู่ใน QR เท่านั้น ไม่มีข้อมูลของรางวัลปรากฏในป้ายที่พิมพ์
4. พนักงาน 1 รหัส ยืนยันรับรางวัลได้ครั้งเดียวเท่านั้น (เช็กซ้ำได้ทั้งจากฝั่งป้ายและฝั่งรหัสพนักงาน แบบอะตอมมิกในฐานข้อมูล กันการสแกนพร้อมกันหลายคนแย่งของชิ้นเดียวกัน) ถ้าลองกรอกรหัสเดิมจากป้ายอื่นจะถูกบล็อกทันที
5. แอดมินสามารถ "รีเซ็ต" ผลของพนักงานรายคนได้ (คืนสต็อก + ปลดล็อกป้าย) ผ่าน API `/api/admin/reset/<รหัสพนักงาน>` กรณีกรอกรหัสผิดคนแล้วยืนยันไปแล้ว — แนะนำให้ทำผ่านเจ้าหน้าที่ที่ไว้ใจได้เท่านั้น
6. อย่าแชร์ไฟล์ `output/admin_manifest.csv` ให้ใครนอกทีมงาน เพราะมีข้อมูลว่าป้ายไหนคือของรางวัลอะไร

## โครงสร้างไฟล์

```
luckydraw/
  server.js                    เซิร์ฟเวอร์หลัก (เชื่อมต่อ Supabase ผ่าน lib/supabase.js)
  lib/supabase.js              ตัวสร้าง Supabase client จากค่าใน .env
  scripts/schema.sql            SQL สำหรับตั้งตาราง+ฟังก์ชันใน Supabase (รันใน SQL Editor ครั้งเดียว)
  scripts/seed.js               โหลดข้อมูลพนักงาน+ของรางวัลขึ้น Supabase + สุ่ม/สับป้าย
  scripts/generate_badges.js    ดึงป้ายจาก Supabase มาสร้าง QR + ชีทป้ายชื่อเปล่า + manifest ลับ
  data/employees.json           รายชื่อพนักงาน (แก้ไข/เพิ่มคนได้ที่นี่)
  data/prizes.json              รายการของรางวัล + สต็อก (แก้ไขจำนวนได้ที่นี่)
  .env                           ค่าลับ (Supabase keys, รหัสแอดมิน) — สร้างเองจาก .env.example ห้าม commit
  public/badge.html             หน้าที่พนักงานเห็นหลังสแกน QR (กรอกรหัส → ตรวจสอบ → ยืนยัน)
  public/admin.html             หน้าแดชบอร์ดแอดมิน (สวิตช์เปิด/ปิด, สถิติ, export)
  public/live.html               จอ Live Wall สำหรับโปรเจคเตอร์หน้างาน
  output/badges.html            ชีทป้ายชื่อพร้อมพิมพ์ (สร้างหลังรัน badges)
  output/admin_manifest.csv     ไฟล์ลับ badge↔ของรางวัล (สร้างหลังรัน badges) ห้ามแชร์
```

## แก้ไขรายชื่อพนักงานภายหลัง

แก้ไฟล์ `data/employees.json` แล้วรัน `npm run seed` ใหม่ได้เลย (จะอัปเดตเฉพาะข้อมูลคน ไม่แตะป้ายหรือผลที่จับฉลากไปแล้ว)

**ของรางวัล/จำนวนป้ายแก้ไม่ได้หลังสร้างป้ายไปแล้ว** เพราะป้าย 205 ใบถูกกำหนดและพิมพ์ตายตัวไปแล้ว — ถ้าต้องการเปลี่ยนรายการ/จำนวนของรางวัลทั้งหมด ต้องลบตาราง `badges` ใน Supabase (SQL Editor: `truncate badges;`) แล้วรัน `npm run seed` ใหม่ทั้งหมด (และพิมพ์ป้ายใหม่)
